# Мониторинг IPSec туннелей в pfSense 2.9+ с помощью Zabbix 7.0 (swanctl)

Решение для автоматического обнаружения (LLD) и мониторинга статуса и скорости IPSec-туннелей на современных версиях **pfSense 2.9+**. 

В последних версиях pfSense устаревшая утилита управления `ipsec` (компонент stroke) была удалена. Данный проект переводит мониторинг на работу с современным интерфейсом **`swanctl`** (StrongSwan v6) и оптимизирован под требования валидатора **Zabbix 7.0**.

## ✨ Особенности решения
* **Человеческие имена туннелей**: Скрипт автоматически сопоставляет технические имена StrongSwan (`con1`, `con4`) с их реальными описаниями (*Description*) из веб-интерфейса pfSense.
* **Высокая производительность**: Метрики собираются через мастер-элемент (Dependent Items). Утилита `swanctl` вызывается один раз в минуту, не создавая нагрузки на процессор маршрутизатора.
* **Отказоустойчивость**: Если IPSec на сервере полностью отключен, скрипт возвращает валидный пустой JSON, не вызывая ошибок парсинга в Zabbix.
* **Готовые графики**: Шаблон включает в себя автоматическую генерацию графиков скорости трафика (Bps) и истории изменения статуса для каждого туннеля.

## 🚀 Инструкция по установке

### 1. Настройка скриптов на стороне pfSense
Создайте два файла в директории `/usr/local/bin/` на вашем сервере pfSense.

#### Скрипт обнаружения: `ipsec_discovery.sh`
Этот скрипт находит активные конфигурации туннелей и сопоставляет их с описаниями из конфигурационного файла pfSense. Скопируйте содержимое файла `ipsec_discovery.sh` из этого репозитория.

#### Скрипт метрик: `ipsec_stats.sh`
Этот скрипт собирает счетчики байт и статус туннеля (0 - Down, 1 - Up, 2 - Только Фаза 1). Скопируйте содержимое файла `ipsec_stats.sh` из этого репозитория.

#### Выдача прав доступа
Выполните в консоли pfSense от пользователя root, чтобы разрешить агенту запуск скриптов:
```bash
chmod +x /usr/local/bin/ipsec_discovery.sh
chmod +x /usr/local/bin/ipsec_stats.sh
```

### 2. Настройка Zabbix Агента на pfSense
В веб-интерфейсе pfSense перейдите в **Services ➔ Zabbix Agent** и в поле **UserParameters** (Расширенные настройки) добавьте следующие строки:

```ini
UserParameter=ipsec.discovery,/usr/local/bin/ipsec_discovery.sh
UserParameter=ipsec.stats[*],/usr/local/bin/ipsec_stats.sh "$1" "$2"
```

> ⚠️ **Важно**: Если у вас настроено много туннелей, увеличьте параметр **Timeout** в настройках Zabbix Агента на pfSense с `3` до `10` или `30` секунд, чтобы скрипт обнаружения успевал обработать большой объем данных. Перезапустите службу агента.

### 3. Импорт шаблона в Zabbix 7.0
1. Скачайте файл шаблона `pfsense_ipsec_swanctl_new.yaml` из этого репозитория.
2. В веб-интерфейсе Zabbix перейдите в **Data collection ➔ Templates ➔ Import**.
3. Выберите скачанный файл (убедитесь, что кодировка файла — чистый UTF-8).
4. Привяжите шаблон **`pfSense IPSec swanctl New`** к вашему хосту pfSense.
5. Чтобы не ждать час, зайдите в настройки хоста ➔ **Discovery rules** и напротив правила `IPSec Tunnel Discovery` нажмите **Execute now**.

## 📊 Сопоставление статусов туннелей
Для удобства в шаблоне используется карта значений (`valuemap`), переводящая коды ответов скрипта в понятный текст:
* **`0`** — **Down** (Туннель полностью лежит, нет ни IKE SA, ни Child SA).
* **`1`** — **Up** (Все отлично, установлены обе фазы, трафик шифруется).
* **`2`** — **Phase 1 Only** (Авторизация пройдена, но Фаза 2 (трафик) не поднялась).
