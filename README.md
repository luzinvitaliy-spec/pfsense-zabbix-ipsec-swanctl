# Мониторинг IPSec туннелей в pfSense 2.9+ с помощью Zabbix 7.0 (swanctl)

Готовое решение для автоматического обнаружения (LLD), мониторинга числового статуса и скорости трафика IPSec-туннелей на современных версиях **pfSense 2.9+** ( StrongSwan v6 / интерфейс управления `swanctl`).

Проект поддерживает **два архитектурных варианта реализации** на выбор: классический прямой опрос агентом и безопасный отказоустойчивый опрос через `cron`-кэширование.

---

## 📐 Выберите вариант архитектуры

### Вариант А. Прямой опрос через Zabbix Agent (Классический)
Скрипты вызываются Zabbix-агентом напрямую при каждом цикле опроса. Требует настройки прав `sudo` для пользователя `zabbix`, чтобы утилита `swanctl` имела доступ к системному сокету StrongSwan.
* **Плюсы**: Простая установка, данные поступают в режиме реального времени без задержек.
* **Минусы**: Требует предоставления прав `sudo` пользователю `zabbix`. На серверах со 100+ туннелями частые вызовы `swanctl` агентом могут создавать нагрузку на процессор.

### Вариант Б. Сбор данных через Cron-кэш (Рекомендуемый / ИБ)
Локальный скрипт на pfSense запускается каждую минуту планировщиком `cron` от имени `root`. Он один раз собирает все данные и раскладывает их в готовые текстовые файлы в `/tmp/`. Zabbix-агент просто считывает эти файлы командой `cat`.
* **Плюсы**: **Абсолютная безопасность**. Пользователь `zabbix` не имеет прав sudo и защищен от командных инъекций (Command Injection). Нулевая нагрузка на CPU — `swanctl` дергается ровно 1 раз в минуту, независимо от количества туннелей и метрик.
* **Минусы**: Задержка обновления данных на графиках составляет до 60 секунд (период работы cron).

## 🚀 Инструкция по установке: Вариант А (Прямой опрос)

1. Скопируйте файлы из папки `pfsense_agent_sudo/` в директорию `/usr/local/bin/` на pfSense:
   * `ipsec_discovery.sh` (скрипт обнаружения)
   * `ipsec_stats.sh` (скрипт сбора метрик)
2. Дайте права на выполнение: `chmod +x /usr/local/bin/ipsec_*`
3. Настройте права `sudo` на pfSense (через пакет Sudo или команду `visudo`), разрешив пользователю `zabbix` вызов утилиты:
   ```text
   zabbix ALL=(ALL) NOPASSWD: /usr/local/sbin/swanctl
   ```
4. В настройках Zabbix-агента в pfSense (**UserParameters**) добавьте:
   ```ini
   UserParameter=ipsec.discovery,sudo /usr/local/bin/ipsec_discovery.sh
   UserParameter=ipsec.stats[*],sudo /usr/local/bin/ipsec_stats.sh "$1" "$2"
   ```

## 🚀 Инструкция по установке: Вариант Б (Через Cron-кэш)

1. Скопируйте файлы из папки `pfsense_cron_cache/` в директорию `/usr/local/bin/` на pfSense:
   * `ipsec_cron_collector.sh` (системный сборщик под root)
   * `ipsec_stats_safe.sh` (безопасный ответчик для агента)
2. Дайте права на выполнение: `chmod +x /usr/local/bin/ipsec_*`
3. Установите пакет **Cron** на pfSense (*System -> Package Manager*) и добавьте ежеминутную задачу от имени `root`:
   * `* * * * * root /usr/local/bin/ipsec_cron_collector.sh`
4. В настройках Zabbix-агента в pfSense (**UserParameters**) добавьте строки (права `sudo` не требуются):
   ```ini
   UserParameter=ipsec.discovery,cat /tmp/zabbix_ipsec/discovery.json 2>/dev/null || echo '{"data":[]}'
   UserParameter=ipsec.stats[*],/usr/local/bin/ipsec_stats_safe.sh "$1" "$2"
   ```

## 🎛️ Настройка на стороне Zabbix (Общая для обоих вариантов)

1. Импортируйте файл шаблона `pfsense_ipsec_swanctl_new.yaml` через **Data collection ➔ Templates ➔ Import**.
2. Привяжите шаблон **`pfSense IPSec swanctl New`** к вашему хосту pfSense.
3. Скрипт обнаружения автоматически вытаскивает текстовые комментарии туннелей (*Description* из GUI pfSense) и передает их в макрос `{#TUNNEL_DESC}`.
4. Чтобы графики и триггеры переименовались на человеческие имена, перейдите в **Item prototypes** правила обнаружения шаблона и добавьте макрос в названия элементов (например: `IPSec: Tunnel {#TUNNEL_DESC} Status`).
5. Нажмите кнопку **Execute now** в правилах обнаружения хоста для моментального поиска туннелей.

## 📊 Карта статусов туннелей
* **`0`** — **Down** (Связь полностью отсутствует).
* **`1`** — **Up** (Туннель полностью активен, трафик шифруется).
* **`2`** — **Phase 1 Only** (Авторизация IKE успешна, но дочерний туннель Phase 2 не поднялся).
